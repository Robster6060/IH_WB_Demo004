# Minimap "Scattered Gold Fragments" — Root Cause Fix — 2026-08-17

**Status: FIXED (2026-08-17)** — Confirmed via PIE grab (ABBEY3, FULLY5, SPARK6): all islands now render as clean, contiguous, solidly-filled landmasses with a single continuous gold outline. Islets and inland-sea holes read correctly at full realm zoom-out.

**Code:** `FIHTerrainCellDiffusion::TraceBoundaryLoops` (`Source/IH_WB_Demo003/WorldBuilder/CellGraph/IHTerrainCellDiffusion.cpp`, private, backs both `TraceCoastlineLoops` and `TraceCoastDistanceBoundaryLoops`). Two bugs, one dominant:

1. **Segment-collection de-dup guard (`NeighborIdx <= CellIdx`) silently dropped ~50% of every real coastline's boundary edges.** The guard assumed a same-predicate pattern (either side of a pair could independently satisfy `InRegion`). For the actual Land/non-Land cross-boundary case, only the in-region cell can ever become the outer-loop `CellIdx` — the out-of-region neighbor fails `InRegion(Cell)` and is skipped outright — so the guard was not just redundant but actively wrong: whenever the out-of-region neighbor's index was *lower* than the in-region cell's, the edge was dropped in both directions.
2. **The loop-chaining walk never verified a chain actually closed** before emitting it as a loop — any truncated/open chain (the direct symptom of bug 1) was unconditionally added to the output.

**Fix:** removed the guard entirely (no de-dup needed — each cross-boundary edge is visited exactly once by construction); added an explicit closure check so a still-broken chain is discarded (with a diagnostic `UE_LOG` if it ever fires) instead of drawn as a fake tiny loop.

**Not the SeaRoots-chord bug.** `IH_WB_Minimap_SeaRoots_Chord_PIE_Checklist_2026-08-09.md` documents a different, already-fixed bug in `PrepareSeaRootsBandRingForMinimapDraw` (densify aborting mid-ring when `MaxOutputVerts` was passed directly into `DensifyClosedPolylineForStroke`, fixed by capping the ring to a uniform vertex count *before* densifying uncapped). That doc's own "open follow-ups" line flagged "ContourGold planform coastline smooth" as unresolved — this doc closes that follow-up, but the fix is unrelated: `PrepareCoastlineForMinimapDraw` (the function the main-coastline draw path actually calls) never passes `MaxOutputVerts` into densify in the first place, so the cap-then-densify pattern does not mechanically apply there. Confirmed by direct code read before reapplying anything — do not conflate the two bugs if either resurfaces.

## Diagnostic trail (for retracing)

1. First hypothesis (screen-space area filter) — confirmed and fixed separately: a minimap ring-size filter computed area in post-projection screen px², which is zoom-dependent and incorrectly discarded every real island when zoomed out to the full realm. Fixed by computing shoelace area from raw world-space points (cm²) instead — `IH_P1C08_MinimapTypes.h::CoastMinimapMinRingFillAreaWorldCm2`.
2. Second hypothesis (interior water noise ponds) — real but minor. Added a water-side connected-components pass in `BuildMeshesFromCellGraph` (`IH_WB_IslandActor.cpp`) mirroring the land-side islet-budget filter (`IH-DEC-020`): any interior Ocean component smaller than `MinLakeCellCount=5` cells is reclassified back to Land. Real inland seas/lakes (`IH-DEC-032`) are unaffected since only the *smallest* components below the floor are filled. This alone reduced loop counts only slightly (e.g. 154 → 151 for one island) — nowhere near enough to explain the symptom.
3. **Real root cause, found by comparing the exact topological component count against the traced loop count on the same graph:** an island's islet-budget log line reported `keptIslets=2` (3 true land components total, computed via exact `Cell.Neighbors` BFS) while `TraceCoastlineLoops` on that identical graph produced `loops=151`. That gap could not be explained by real islets or real lake holes — it meant the boundary *tracer itself* was fragmenting a topologically-single landmass into ~150 small broken pieces. Reading `TraceBoundaryLoops` line by line found the two bugs above.
4. **Quantitative confirmation via automation test**, not just PIE: `InvisibleHand.WorldBuilder.TerrainCellGraph.NestedInletShape`'s own diagnostic log went from `loopCount=9 loopSizesDesc=29,18,15,9,5,5,4,3,2` (pre-fix) to `loopCount=2 loopSizesDesc=259,10` (post-fix) — the main loop's vertex count grew ~9x and total loop count dropped from 9 to 2, with zero discarded-open-chain warnings logged.

## If this resurfaces

- Check the new diagnostic log line first: `IHTerrainCellDiffusion::TraceBoundaryLoops: segments=%d closedLoops=%d discardedOpenChains=%d discardedOpenChainVerts=%lld` — only logged when `discardedOpenChains > 0`. A nonzero count here means the graph is hitting a *different* edge-collection gap than the one fixed (e.g. a genuine `FindSharedEdge` tolerance failure between two adjacent cells' boundary polygons, not the de-dup guard), and needs its own investigation — do not assume it's the same bug reappearing.
- Compare the islet-budget log's `totalComponents`/`keptIslets` (topological, exact) against the per-island `loops=` count in the same log — a large gap between them is the fastest signal that the boundary tracer, not the terrain generator, is the problem.
